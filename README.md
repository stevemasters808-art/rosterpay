# RosterPay

Static penalty-rates calculator for the General Retail Industry Award (MA000004) and the Hospitality Industry (General) Award (MA000009). Stage 1 demand test. No framework, no build for deployment, no backend.

## Files

| File | Purpose |
|---|---|
| `index.html`, `nsw.html` … `nt.html` | One page per state. Generated by `build-pages.py`; edit the template there, not the HTML. |
| `engine.js` | Pure calculation. Browser global `RosterPay`, or `require()` in Node. |
| `app.js` | Form, result rendering, payslip comparison, analytics events. |
| `style.css` | Styles. |
| `rates.json` | Award rates, penalty and overtime percentages, junior bands, effective-from dates. |
| `holidays.json` | Public holidays 2026 and 2027 per state, with part-day windows and regional flags. |
| `test.js`, `test.html` | 12 worked examples checked to the cent against the FWO pay guides. `node test.js` or open `test.html`. |
| `build-pages.py` | Writes the HTML pages, `sitemap.xml`, `robots.txt`. Python 3, stdlib only. |
| `img/` | Logo, favicon, wordmark, share image (SVG). |

## Run locally

Any static server, for example:

```bash
python -m http.server 8080
```

`fetch()` of the JSON files does not work from `file://`.

## Deploy

Push the folder to GitHub Pages or Cloudflare Pages. No build command. Set `SITE` in `build-pages.py` to the real domain and rerun it before the first deploy so canonical URLs and the sitemap are right.

## Configuration

In `app.js`:

- `GOATCOUNTER`: GoatCounter endpoint, e.g. `https://rosterpay.goatcounter.com/count`. Cookie-free. Events sent: `calc`, `payslip-compare`, `return-visit`, `app-waitlist`. Empty string disables analytics.
- `WAITLIST_URL`: Google Form or Formspree URL opened by the "Get the Android app" button. Empty string shows a "coming soon" note instead; the click is still counted.

## Updating rates

1. New FWO pay guide (usually late June): add a new object to `rates[]` for the award with the new `effectiveFrom` and hourly rates. Leave old entries so past shifts still price correctly.
2. Junior phase-in steps for Retail are already in `rates.json` through 1 July 2029 per determination PR813655.
3. New year of public holidays: append to `holidays.json`, rerun `build-pages.py`.
4. Update `checked` in `rates.json`. Run `node test.js`. Add a test for any new figure.

## Rules the engine applies

- Rates: junior rate = adult hourly × percent rounded to the cent; each penalty or overtime rate = that hourly × percent rounded to the cent; each line = hours × rate rounded to the cent. Matches the pay guide.
- Highest single rate per minute, no stacking. Casual percentages already include the loading.
- Overtime: Retail, outside span or over 9 ordinary hours a shift (11 if the roster option is ticked) or over 38 a week; Hospitality, over 11.5 ordinary hours a shift (12 casual) or over 38 a week. Weeks start on the pay period start date. Part-time agreed weekly hours replace 38 when given.
- Hospitality evening ($2.95) and night ($4.42) additions apply per hour or part hour on non-overtime minutes only. Hospitality casual overtime has no loading. Hospitality has no separate public holiday overtime rate; public holiday hours are paid at the public holiday rate.
- Unpaid breaks are removed from the cheapest minutes of the shift.
- Shifts across midnight are priced minute by minute by the actual calendar day.

## Not covered

Allowances, shiftwork, baking, apprentices, junior office classifications, casino, annualised salary, minimum engagement periods, leave, tax, super, enterprise agreements, other awards.

## Before public launch

Drawn from shipped-app threads in the owner's research database (FB-182, YT-r4R_Hlw7sbo, CZ-0151).

1. Analytics live before the first visitor: set `GOATCOUNTER`, confirm the four events arrive.
2. Click every control on a phone and a desktop: add and remove shifts, every toggle, both awards, all states, payslip compare, app button, every footer link. Read all copy once.
3. Private beta first: give the link to 4 to 10 shift workers you know (retail and hospitality, at least one casual, one junior). Two weeks. Ask for a real payslip comparison, not an opinion. Fix what they trip on, then post publicly.
4. No secrets in the repo. The site has none; keep it that way (no API keys in `app.js`).
5. Set `SITE` in `build-pages.py` to the real domain, rerun, check canonical URLs and `sitemap.xml`.
6. Submit the sitemap in Google Search Console after deploy.

Design rules for any new screen, web or Android: `DESIGN.md`.

## Week-12 gates (fixed 22 October 2026)

Pass: 1,000+ organic sessions a month, 40%+ complete a calculation, 15%+ 30-day return, 150 waitlist sign-ups or 5% click-through on the app button. Fail: under 300 sessions, under 25% completion, under 5% return, or under 50 sign-ups. Kill: FWO adds pay calculation to Record My Hours, or PACT ships a mobile shift log.
